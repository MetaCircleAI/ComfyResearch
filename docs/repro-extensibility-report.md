# W7 friction diary — paper-repro reimplementation (W7-E1..E4) vs PR #54

Scope compared: PR #54 (`repro/paper-templates`, 93 files, +10041/-241, single PR, CI red) vs the
W7 wave (`feat/w7-e0-runtime-lift` → `feat/w7-e1-node-defs` → `feat/w7-e2-trainer` →
`feat/w7-e3-pipeline` → `feat/w7-e4-templates`, ~100 files across E1..E3 commits plus 9
E4 working-tree files, each stage green before the next).

Evidence base: `gh pr diff 54`, `gh run view 29100997401 --log-failed` (PR #54's last CI run,
2026-07-10, all three jobs failing), and `git diff 310d890~1..HEAD` plus this working tree.

## The three old CI death causes

### 1. Invariant expected-list failures (frontend drift guard job)

**Old failure surface.** PR #54's frontend job died on hand-maintained expected lists that had to
be updated in lockstep with every node/param addition:

- `AssertionError: expected [ 'trainingLengthMode', …(7) ] to deeply equal [ 'trainingSteps', …(5) ]`
  — a test pinned the trainer's param-key list; adding `trainingLengthMode`/`trainingEpochs` broke it.
- `AssertionError: expected [ 'cifar10_dataset', …(4) ] to deeply equal [ 'gaussian_blob_dataset', …(3) ]`
  — a test pinned the vision-dataset kind list; adding `cifar10_dataset` broke it.
- codegen golden manifest mismatch (`expected { version: 1, …(2) } to deeply equal …`) — new
  template JSONs not reflected in the committed snapshot.

**How the new architecture changed it.** Expected lists are now *derived, not duplicated*: the
manifest (`comfy_research/generated/node_manifest.json`) is generated from the def files, and the
invariant tests compare against the manifest instead of a second hand copy. In W7-E1 the eight
node types entered through `comfy_research/nodes/definitions/**` def files; `node_kind.py`,
`node_params.py`, `node_capabilities.py`, `generatedNodeSpecs.ts` and the connection/hint goldens
were regenerated by tooling in the same commit, so no list could disagree with another.
The catalog membership test (`test_node_catalog_from_manifest.py`) asserts *subset* membership
(`manifest_visible <= catalog_ids`), so a new type cannot fail it by omission.

**What this wave hit.** Exactly one golden needed regeneration: adding the two template JSONs
made `codegen.golden.test.ts` fail (93 fixtures vs 91 committed). Fix was the sanctioned tool run
`npm run generate:codegen-golden` — one command, not a hand edit. Same failure *class*, but it is
now a one-command drift guard rather than N scattered lists.

**Remaining hand surfaces.** `_MAIN_CATALOG_NODE_ORDER` in `comfy_research/api/node_catalog.py`
(curated sidebar order — omission is cosmetic, new types sort to category end, but paper-repro
placement still required a hand edit of 3 lines in E4); `_HIDDEN_CATALOG_NODE_TYPES`; the golden
snapshots still need their regen command run when fixtures change.

### 2. Cascade syntax error (e2e / vite build job)

**Old failure surface.** PR #54's build died with
`frontend/src/components/ResearchCanvas.tsx:6516:8: ERROR: Unexpected ")"` — a hand edit deep in
the 6500+-line canvas monolith (per-node wiring for the new socket/edge special cases was spliced
directly into `ResearchCanvas.tsx` and `AddNodeSearchModal.tsx`) left an unbalanced parenthesis
that killed the whole vite build, and with it the e2e job.

**How the new architecture changed it.** Per-node registration no longer touches
`ResearchCanvas.tsx` or `AddNodeSearchModal.tsx` at all: the canvas and Add-Node modal are driven
by the generated node specs and connection rules. In this wave's diff, PR #54 hand-edited
`ResearchCanvas.tsx` / `AddNodeSearchModal.tsx` / `nodeRegistrySpec.ts` / `nodeRegistryMetadata.ts`
for all 8 types; the W7 wave touched none of the first two per node (grep of `git diff
310d890~1..HEAD` shows the 8 type ids absent from both files). The remaining frontend hand code
per node is its display component (`*Node.tsx`) and defaults file — small, isolated files whose
syntax errors fail only their own module, plus generic (not per-node) edits to shared plumbing
like `connectionRules.ts` and `curveSeriesAppend.ts` in E1/E3.

**What this wave hit.** Nothing in this class. E4 is backend/data-only; `npx vitest run` (14
files, 131 tests) and the codegen-golden build path pass with zero frontend source edits.

**Remaining hand surfaces.** The per-node `*Node.tsx` components and shared graph helpers are
still hand-written TypeScript; a syntax error there still breaks the build — it is just no longer
*required* for registration, and the blast radius of "add a node type" no longer includes the
canvas monolith.

### 3. httpx collection error (backend pytest job)

**Old failure surface.** PR #54's entire backend suite died at *collection*:
`RuntimeError: The starlette.testclient module requires the httpx2 package to be installed` raised
while importing `test_repro_template_manual_rebuild.py` → `Interrupted: 1 error during collection`
→ exit 2 with **zero tests run**. One missing test dependency took down the whole job, hiding
every other signal.

**How the new architecture changed it.** `httpx>=0.27` is pinned in `requirements.txt` (line 3) and
present in the `comfyresearch` env, so the same import now succeeds (with a
`StarletteDeprecationWarning` advising a future move to `httpx2`). The lifted
`test_repro_template_manual_rebuild.py` in E4 imports `fastapi.testclient.TestClient` at module
top level exactly like the old one; full-suite collection (484 passed, 6 skipped) confirms no
collection-time landmine.

**What this wave hit.** Nothing; the deprecation warning is the only residue.

**Remaining hand surfaces.** The starlette→httpx2 migration is parked debt: when starlette drops
classic httpx support, the same collection-error shape returns unless `httpx2` is added to
requirements first. Module-level `TestClient` imports keep this a collection-time (whole-job)
failure mode rather than a per-test one.

## Per-node-type files touched: PR #54 vs W7 wave

Method: for each of the 8 node types, count files in the respective diff whose patch text mentions
the type id (snake_case + camelCase variants). PR #54 = `gh pr diff 54`; W7 wave =
`git diff 310d890~1..HEAD` + E4 working tree (Makefile, node_catalog.py, seed tool, 3 test files,
2 template JSONs, codegen golden). "gen" = files produced by generators/tools
(`comfy_research/generated/*`, `frontend/src/generated/*`, frontend `__snapshots__/*`, template
JSONs); "hand" = hand-authored non-test files; "test" = test files.

Reading the table honestly:

- **Raw totals are similar or higher in the wave** — because the wave carries *more* generated
  artifacts (generatedNodeSpecs.ts, connection/hint goldens didn't exist in PR #54's era) and more
  tests. Those are regenerated/added by command, not maintained by hand.
- **The hand column drops for every type** (e.g. keskar model 13→9, vgg11 12→9, curve_series_viz
  9→7), and the *composition* changes more than the count: PR #54's hand set for each type included
  the 4-file frontend registry splice (`nodeRegistrySpec.ts`, `nodeRegistryMetadata.ts`,
  `AddNodeSearchModal.tsx`, `ResearchCanvas.tsx`) — the cascade-error surface — while the wave's
  hand set is the def file (`comfy_research/nodes/definitions/**`), the engine adapter/builder
  hookup (`model_builders.py` / `prepare_config.py` / `node_builder_registry.py`), the display
  component + defaults, and shared per-batch files (seed tool, node_catalog order) that each
  mention several types at once.
- **Pure-frontend types show the pattern most cleanly**: `curve_series_viz` in the wave is 1 def
  file + 1 component + shared helpers; every registry surface it appears in is generated.
- Counting only *registration* touchpoints (registry/spec/metadata/catalog/generated files, i.e.
  excluding the node's own component, engine logic, tests, templates): PR #54 needed ~10-15 per
  node (4 generated + 4 frontend registry hand-splices + catalog + modal/canvas wiring); the wave
  needs 1 def file + 0-2 adapter registrations, with 7-9 generated files refreshed by the
  manifest/spec/golden generators.

## E4-specific friction notes (this session)

- The reference branch's committed template JSONs had **drifted from their own seed tool**: they
  contained run artifacts (loss histories, curve rows, sampler results, moved positions) and a
  Keskar trainer hand-tuned to `trainingSteps=1000/batchSize=5000`, vs the tool's
  `19600/256`. The codex ruling (tool-generated, never hand-edited) is now enforced by
  `test_repro_template_determinism.py::test_committed_template_matches_regenerated`.
- Only two facts needed fixing when lifting the 701-line seed tool: the import path
  (`engine.cyclic_schedules` → `engine.optimizers.cyclic_schedules`) and, in the lifted tests, the
  `prepare_trainer_run` module (`engine.trainer_run` → `engine.runs.trainer_run`) plus the
  validate-only patch target (`engine.trainer_run.build_vision_numpy_arrays` →
  `engine.trainer.dataset_materialize.build_vision_numpy_arrays`). All node type ids and data keys
  in the tool checked clean against the current generated manifest — zero template-content edits.
- `data/graph_library/templates/` is *not* gitignored (`.gitignore` explicitly negates
  `!data/graph_library/templates/**/*.json` under the broad `data/**/*.json` ignore), and
  `api/graph_library.py` reads canonical `templates/{id}.json` — the reference layout carried over
  unchanged.
